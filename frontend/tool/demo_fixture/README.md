# 시연 모드

중간 발표 시연 영상용 실행 방법이다. **debug 빌드에서만** 켜진다.

- 로그인, 카드 연결(ONB-01~03): 실제 서버와 CODEF를 그대로 쓴다.
- 카드 선택(ONB-04)부터 거래내역(ONB-05), 소비 분석(ONB-06), 플랜 생성(ONB-07A·B), 월간 플랜(PLAN-01)까지: 시연 자료의 값을 서버 응답처럼 보여 준다. ([lib/core/demo/demo_fixture_adapter.dart](../../lib/core/demo/demo_fixture_adapter.dart))
- 앱의 오늘 날짜를 시연 자료 기준일(기본 2026-10-01)로 고정한다.

시연 자료는 세 카드 월간 플랜 시뮬레이션 결과다. 두 사람의 거래를 합친 실험이라 한 사람의 실제 계획이나 카드사가 지급한 혜택이 아니다. 발표에서는 시뮬레이션 값이라고 밝힌다.

## 1. 시연 자료 파일 만들기

```bash
python tool/demo_fixture/make_demo_fixture.py \
  --plan <경로>/01_소비분석_예측_월간플랜_전체.json \
  --experiment <경로>/시연데이터.json
```

- 결과는 `assets/demo/demo_fixture.json`에 저장된다. 실제 소비에서 나온 숫자라서 `.gitignore`로 git에 올리지 않는다.
- 원본 자료도 저장소 밖에 둔다.
- 파일이 있으면 release 빌드에도 묶이므로(쓰지는 않음) 촬영이 끝나면 지운다.
- `--scenario`: BC 8월 실적 가정. 기본 `BC_AUG_300000` (`BC_AUG_0`도 있음)
- `--as-of`: 시점. 기본 `2026-10-01T00:00` (9월 소비 분석 → 10월 플랜)
- `--merchants`: ONB-05 최근 거래 5건의 가맹점명. 최근 거래부터 쉼표로 구분 (예: `--merchants "GS25,스타벅스,..."`). 시연 자료에 가맹점명이 없어 넣지 않으면 업종 이름으로 표시

| 화면 | 시연 자료에서 가져오는 값 |
|---|---|
| ONB-04 | 카드 3장 (카드 번호는 `0001`처럼 임의 번호) |
| ONB-05 | 분석한 달의 카드별 실제 사용 금액·건수, 결제 예시 5건 (가맹점명은 `--merchants`로 넣고, 없으면 업종 이름) |
| ONB-06 | 소비 분석 응답 |
| ONB-07A·B | 플랜 응답. 생성은 4초 뒤 완료되고, 같은 달에 다시 만들어도 "이미 있음"이 나지 않는다 |
| PLAN-01 | 플랜과 업종별 권장 카드 응답 |

## 2. 실행

```bash
flutter run --dart-define=DEMO_MODE=true --dart-define=USE_FAKE_API=false
```

- 로그인·카드 연결은 로컬 백엔드(기본 `http://10.0.2.2:8080`)로 간다.
- 시연 자료만 확인하려면 `--dart-define=INITIAL_ROUTE=cardSelect`로 ONB-04부터 시작한다.
- 켜지면 로그에 `[demo] 시연 모드: 기준일 ...`이 찍힌다. 자료 파일이 없으면 경고를 남기고 평소처럼 실행된다.
- 시연 자료를 `--dart-define`에 직접 넣지 않는 이유: Windows에서 명령줄 길이 제한을 넘어 빌드가 실패한다.

## 촬영할 때 주의

- ONB-05에서는 **1개월**을 선택한다. 소비 분석은 1개월(분석한 달) 자료라서 3·6개월을 고르면 ONB-05 합계와 ONB-06 분석 기간이 맞지 않는다. (3·6개월은 직전 달 거래를 더한 값)
- ONB-06에서 예산을 바꾸지 않는다. 플랜은 미리 계산한 값이라 바꾼 예산이 반영되지 않는다.
- ONB-04의 카드 3장은 실제로 연결한 카드사와 상관없이 시연 자료의 카드다.
- PLAN-01의 사용 금액은 월초 시점이라 0원이다. 플랜 변경 안내, PLAN-02·03 상세는 시연 모드에서도 기존 동작(앱 안 재계산, 가짜 기본값) 그대로다.
