# 카드 배분 알고리즘 연결 범위

## 월간 플랜: CP-SAT

`CpSatPlanStrategyRunner`는 기존 `PlanStrategyRunner` 계약을 구현한다. 플랜 생성 서비스가 `PlanStrategyInput`에 확정된 업종별 예산, 보유카드 ID와 카드 상품 ID, 카드별 전월실적, 계산 시간 제한을 채워 호출한다. 이 클래스는 DB를 수정하거나 카드번호를 받지 않는다.

1. 카드별·업종별 사용액을 0 이상의 정수 변수로 만든다.
2. 각 업종의 카드별 사용액 합계를 그 업종 예산과 정확히 같게 묶는다. 총소비를 늘리지 않는다.
3. 혜택 규칙 조회 서비스를 통해 카드 상품의 비율 혜택과 전월실적 구간을 읽는다. 기본 설정에서는 원문 대조가 끝난 규칙만 쓴다.
4. 비율 혜택, 규칙별 월 한도, 한도 묶음의 공유 월 한도를 목적식에 반영해 예상 혜택을 최대화한다.
5. 결과의 카드별 사용액을 기존 `BenefitCalculator`로 다시 계산하고, 예산 보존을 검사한 뒤 `PlanStrategyResult`를 반환한다. `solverStatus`는 **구현된 수학 모델**의 풀이 상태다.

## 결제 한 건: 즉시 혜택

`ImmediateDiscountSelector.choose`는 결제 업종·금액과 보유카드별 **이번 달 이미 사용한 업종별 금액**을 받는다. 각 카드의 결제 전후 혜택을 기존 계산기로 구하고, 증가분이 가장 큰 카드를 고른다. 동률이면 보유카드 ID가 작은 카드를 고른다. 카드 사용 내역을 변경하거나 DB에 저장하지 않는다.

## 실제 데이터 연결 전 확인

- `stg_*` 원문·구조화 테이블에 데이터가 있다는 사실만으로 계산할 수 없다. `BenefitRuleQueryService`가 읽는 최종 카드·혜택 규칙 테이블에 MVP 카드가 승격되고, 사용할 규칙의 원문 대조 상태를 확인해야 한다. 기본 설정 `READY_ONLY`에서 확인된 규칙이 없으면 CP-SAT 실행기는 실패 결과를 돌려준다.
- 월간 입력은 업종별 **합계**다. 거래 순서, 현재 달에 이미 결제한 내역, 가맹점별 혜택, 일·횟수 한도, 정액 할인, 실적 제외 결제, 다음 달의 예상 혜택은 이 계약만으로 최적화할 수 없다. 해당 조건까지 적용했다고 표시하면 안 된다. 현재 혜택 계산기도 같은 제한을 가진다.
- 결제 한 건의 즉시 혜택 선택에는 이번 달 사용액과 전월실적이 필요하다. CODEF 거래를 받아 업종을 확인하고, 취소·중복·미분류 거래를 처리한 뒤 호출해야 한다. `ImmediateDiscountSelector`는 호출할 준비가 된 계산 구성요소이며, CODEF 수집이나 API 연결 자체는 이 변경에 포함되지 않는다.
- 월간 플랜이 평소 카드 사용보다 항상 이득인 것은 아니다. 예상 소비와 실제 소비가 달라지면 다시 계산하고, 결과 비교와 사용자 선택을 별도 서비스 흐름에서 처리해야 한다.
